# Bug Fixes Summary — Deep Audit 2026-04-17

## Critical Fixes Applied

### 1. Fee Double-Counting Bug (kalshi_continuous_trader.py)
**File**: `merid/trading/kalshi_continuous_trader.py`
**Lines**: 447-482, 426-442

**Problem**: `OrderTracker.record_fill()` was adding fees without accounting for already-recorded estimated fees from `record_order()`. This caused fees to be double-counted for resting orders that filled.

**Fix**: 
- Added `estimated_fee_cents` field to resting order storage in `record_order()`
- Modified `record_fill()` to compute fee delta (actual - estimated) instead of adding full fee
- Added defensive check for missing fill price

**Impact**: Accurate fee tracking for P&L calculations and risk management.

---

### 2. None Dereference Bug (consensus.py)
**File**: `merid/prediction/consensus.py`
**Lines**: 888-927

**Problem**: Multiple `fetchone()[0]` calls without checking if fetchone() returned None. This would crash if tables were empty.

**Fix**: 
```python
# Before:
total_opinions = conn.execute("SELECT COUNT(*) FROM pred_opinions").fetchone()[0]

# After:
row = conn.execute("SELECT COUNT(*) FROM pred_opinions").fetchone()
total_opinions = row[0] if row else 0
```

**Impact**: Prevents crashes on empty database states.

---

### 3. Division by Zero Bug (position_sizer.py)
**File**: `merid/event_venues/kalshi/position_sizer.py`
**Lines**: 597-611

**Problem**: `_pf_scale()` could divide by zero when `pf_full_kelly_at == pf_min_for_scaling` (range_pf becomes 0).

**Fix**:
```python
range_pf = cfg.pf_full_kelly_at - cfg.pf_min_for_scaling
if range_pf <= 0:
    # Degenerate case: pf_min == pf_full, jump directly to full scale
    return 1.0
progress = (profit_factor - cfg.pf_min_for_scaling) / range_pf
```

**Impact**: Prevents ZeroDivisionError when PF scaling parameters are equal.
