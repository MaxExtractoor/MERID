### Issue 2 — CRITICAL: `KalshiRiskScreen` `RISK_ALERTS` response shape mismatch — alerts table always empty

**File:** `web/react/src/views/KalshiRiskScreen.tsx:69-73, 81-99`

The component expects `{ alerts: RiskAlert[] }` where each `RiskAlert` has fields `id, timestamp, severity, type, description, source, status`.

The backend handler at `web/api/real_data_endpoints.py:1043` (`GET /api/v1/risk/alerts`) returns a **bare array** `List[Dict]`, not a wrapped object `{ alerts: [...] }`. Each element uses the key `level` (not `severity`), `message` (not `description`), `timestamp` (not ISO string — it uses `now_iso` which is `.isoformat()+"Z"`), and lacks a `source` or `status` field entirely.

Result: `polledAlerts?.alerts?.forEach` always iterates zero items because `polledAlerts` is an array, not `{ alerts: [...] }`. The alert table is always empty unless WS alerts arrive.

**Fix:** Either wrap the backend return value: `return {"alerts": alerts}` in `real_data_endpoints.py:1107`, or change the component to handle the bare array.

### Issue 6 — HIGH: `OperatorDashboard` Day P&L always shows `--`

**File:** `web/react/src/views/OperatorDashboard.tsx:42-44, 84-89`

The component fetches `API_ENDPOINTS.KALSHI_PNL` (`/api/v1/kalshi/pnl`) and expects `{ daily_pnl_usd?, daily_total_pnl_usd? }`. The backend at `kalshi_api.py:3413` returns `daily_pnl_usd` (confirmed). However, the resolution logic in `OperatorDashboard.tsx:84-89` is:

If `daily_pnl_usd` is `0.0` (zero), `typeof 0.0 === 'number'` is `true`, so it correctly returns `0`. That is fine. The `--` symptom means the fetch is failing (e.g., 401 or 500) or `kalshiPnl` is null. Check backend startup logs for fills ledger initialization.

The `MetricCard` for Day P&L at line 135 passes `delta={kalshiDayPnlUsd ?? undefined}`. When `kalshiDayPnlUsd` is `null`, `delta` is `undefined`, so no delta indicator is shown. This is correct behavior but can mask zero vs null.
